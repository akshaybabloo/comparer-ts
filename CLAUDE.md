# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

`comparer-ts` is a TypeScript library (text, folder and image diffing) whose logic is written in Rust and compiled to WebAssembly. The sibling Electron app `../comparer` is its main consumer, depending on the published package from npm (`comparer-ts@^1.1.0`) rather than a local link — so a change to the public API or result shapes only reaches the app once it is released and the app's dependency is bumped.

## Commands

Requires Rust with the `wasm32-unknown-unknown` target, `wasm-pack` and pnpm. In this shell `pnpm` may not be on PATH — use `corepack pnpm`.

| Task                                    | Command                                                                                |
| --------------------------------------- | -------------------------------------------------------------------------------------- |
| Full test (wasm build + Rust + TS)      | `pnpm test`                                                                            |
| Build `dist/`                           | `pnpm run build`                                                                       |
| Build wasm only (`crates/comparer/pkg`) | `pnpm run build:wasm`                                                                  |
| Regenerate TS types (`src/bindings`)    | `pnpm run build:bindings`                                                              |
| Typecheck                               | `pnpm run typecheck`                                                                   |
| Format TS/JSON/MD                       | `pnpm run fmt`                                                                         |
| Rust tests                              | `cargo test` (or `cargo test -p text-diff`, `cargo test -p folder-diff --test native`) |
| TS tests only                           | `pnpm run test:ts` (or `pnpm exec vitest run -t "generateDiff"`)                       |

CI (`.github/workflows/ci.yml`) additionally enforces `cargo fmt --all --check`, `cargo clippy --all-targets -- -D warnings`, and `prettier --check` (printWidth 120). Run these before considering Rust or TS changes done.

## Architecture

Two generated directories are gitignored and must exist before TS code compiles or tests run:

- `crates/comparer/pkg/` — wasm-pack output, imported directly by `src/index.ts` (`../crates/comparer/pkg/comparer.js`). Stale after any Rust change until `pnpm run build:wasm` is rerun; `vitest` does not rebuild it.
- `src/bindings/` — TypeScript types generated by ts-rs. Types with `#[cfg_attr(feature = "ts", derive(TS), ts(export))]` are written out when `cargo test` runs; `.cargo/config.toml` sets `TS_RS_EXPORT_DIR` to `src/bindings`. Never hand-edit these; change the Rust struct and rerun `cargo test`.

### Rust workspace (`crates/*`)

- `text-diff`, `folder-diff`, `image-diff` — the actual algorithms, plain Rust crates that build natively and for wasm. Each uses rayon natively and runs sequentially under `cfg(target_arch = "wasm32")`; keep both paths working. `folder-diff` also has a native-only `native.rs` (`diff_folders`, `list_folder`) that reads the filesystem. Serde/ts-rs derives are behind optional `serde`/`ts` features.
- `comparer` — the only `cdylib`. A thin `wasm-bindgen` adapter over the three crates (`text.rs`, `folder.rs`, `images.rs`, `hasher.rs`). Structured results cross the boundary as JSON strings (parsed in TS) or typed arrays; errors become `CompareError` → thrown JS `Error`. It enables the `ts` feature on its dependencies, which is why `build:bindings` tests it together with them.

### TypeScript layer (`src/index.ts`)

Wraps the raw wasm exports in the public camelCase API (`generateDiff`, `generateInlineDiff`, `compareFolders`, `compareImages`, `compareImagesRgba`, `createImagePair`) and re-exports the generated binding types. Image result types (`ImageDiff`, `CompareImagesOptions`) are handwritten here because ts-rs can't describe pixel buffers. Result objects use snake_case fields (matching Rust) while function/option names are camelCase.

Important cross-boundary patterns:

- **Folder diff is host-driven.** Wasm has no filesystem, so the caller supplies listings (`FsEntry[]`) and a `read` callback. `compareFolders` constructs a wasm `FolderComparer`, fetches `pending_hashes()` (only same-size files on both sides), streams each file through a wasm `Hasher` with a concurrency-limited worker pool, records `set_hash`/`set_error`, then calls `finish()`. Read failures become `unknown` entries, not rejections.
- **Wasm memory is manual.** Every wasm-bindgen object (`FolderComparer`, `Hasher`, `ImageComparison`, `ImagePair`) must be `.free()`d; the existing code uses try/finally and settles all workers before freeing. `finish()` consumes the comparer. Buffers from `take_diff_rgba`/`take_diff_png` are copied out of wasm memory before the comparison is freed.

### Build/packaging

Vite library mode (`vite.config.js`) with `vite-plugin-wasm` inlines the `.wasm` into a single ES module `dist/comparer.es.js`; `vite-plugin-dts` emits `dist/index.d.ts`. Only `dist` is published.

The README is the user-facing API reference (field tables, tolerance semantics, trailing-newline behaviour); update it alongside any change to public behaviour or result shapes.
